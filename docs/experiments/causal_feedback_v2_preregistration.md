# Causal feedback ablation v2 — preregistration

Status: **PREREGISTERED / NOT YET TARGET-SCORED LIVE**

Issue: #60

## 1. Question

Does **target-relevant scalar feedback** causally improve the candidates generated by an otherwise identical iterative language-model search policy?

This experiment intentionally narrows the Perquire claim. It does **not** test, by itself, whether high cosine equals semantic recovery, whether the original hidden text can be reconstructed, or whether gains generalize across embedding models.

The causal claim tested here is:

> Holding generation opportunities, prompt structure, chronological candidate history, model configuration, and evaluation count fixed, feedback numbers that contain information about the correct target should lead to better future candidates with respect to that target than target-irrelevant feedback numbers.

## 2. Why v2 is necessary

Scaling v1 cannot identify this mechanism claim.

- The recovered v1 aggregate has 1080/1080 expected cells but only 78 valid (~7.22%), far below the preregistered 95% operational gate.
- V1 adaptive search differed from controls in more than scalar feedback: prompt structure, best-candidate state, history, phase, and generation opportunity also differed.
- The v1 exploration/refinement transition depended on the requested budget, so B=2,4,8,16,32 were not nested truncations of one fixed policy.
- The primary outcome was the optimized embedder's own cosine, so semantic recovery was not independently established.
- Replicates are stochastic samples within targets; targets, not replicates, are the primary inferential units.

V2 therefore tests the mechanism first, before another broad scaling claim.

## 3. Frozen causal arms

All three arms use the **same iterative proposer** and **same prompt template**. The proposer receives the chronological text of all candidates it has generated so far and one numeric feedback value for each prior candidate.

Only the source of those numeric values changes.

### A. `true_feedback`

For candidate `x_t`, feedback shown on later steps is:

`f_t = cosine(E(x_t), E(source_target))`

### B. `decoy_feedback`

For candidate `x_t`, feedback shown on later steps is:

`f_t = cosine(E(x_t), E(decoy_target))`

The decoy target is paired **prospectively and deterministically** before any candidate generation. Each case is paired with the next case in corpus order, wrapping at the end. A case is never paired with itself.

This arm preserves a realistic, target-derived scalar signal while destroying relevance to the correct target.

### C. `null_feedback`

Every prior candidate receives the same frozen feedback value:

`f_t = 0.0`

This arm preserves the same prompt fields and history length while removing scalar information.

## 4. What is held identical

Across arms, for a target and replicate:

- generation model and provider configuration;
- temperature, max tokens, retry/failure policy;
- proposer system/user prompt template;
- chronological candidate-history format;
- one logical LLM generation opportunity per step;
- one candidate selected from each generation response by the same parser rule;
- number of target-similarity evaluations;
- embedding model used for the optimization outcome;
- maximum trajectory length;
- checkpoint definitions;
- cache/replay semantics;
- artifact schema.

The arm label itself must not be disclosed to the model. Prompts describe the numbers neutrally as `feedback`, not as true/false/decoy/null.

## 5. Nested trajectory and budgets

There is one trajectory per `(target, replicate, arm)` with maximum length **32**.

Preregistered checkpoints are:

`2, 4, 8, 16, 32`

Checkpoint B is a truncation of the exact same trajectory, not a separately generated run. Therefore:

`trajectory@2 ⊂ trajectory@4 ⊂ trajectory@8 ⊂ trajectory@16 ⊂ trajectory@32`

No exploration/refinement schedule may depend on the requested checkpoint. The proposer policy is step-local and fixed before execution.

## 6. Arm order

Method order must not be fixed to `true → decoy → null`.

For each target, order is deterministically counterbalanced from a versioned hash of `(case_id, replicate, experiment_version)`. The same deterministic rule must be testable offline and persisted in the artifact.

This prevents provider time/order from being perfectly confounded with arm.

## 7. Outcomes

### Primary mechanism outcome

For each target and checkpoint B:

`Δ_decoy_i(B) = best_true_i(B) - best_decoy_i(B)`

`Δ_null_i(B) = best_true_i(B) - best_null_i(B)`

Primary interpretation is target-paired. Replicates, if present, are first aggregated within target.

### Co-primary trajectory evidence

Because a maximum can reward variance, the artifact and analysis must also report:

- all candidate target scores;
- best-so-far curve;
- mean candidate target score by arm/checkpoint;
- median candidate target score by arm/checkpoint;
- per-step improvement over prior best;
- area under the best-so-far curve over steps;
- proportion of steps that improve the previous best;
- next-step score as a function of prior feedback/history when estimable.

No success claim may rely only on a single final maximum.

### Secondary semantic outcome

**Not part of the primary causal gate.**

A later, separately frozen experiment may score candidates using a held-out embedding model, independent semantic judge, retrieval neighborhood, or human evaluation. Positive v2 causal feedback results in the optimized space do not automatically establish semantic inversion.

## 8. Inferential unit and replication

The primary inferential unit is the **target case**.

Provider replicates are repeated stochastic trajectories within the same target and are not counted as independent targets.

Primary summaries must therefore either:

1. aggregate replicate-level effects within each target and analyze the resulting target-level paired effects; or
2. use an explicitly hierarchical model with target as the higher-level unit.

Naive `stderr = stdev / sqrt(targets × replicates)` is prohibited.

## 9. Initial sample and escalation

The corpus remains the frozen 24-case v1 corpus for comparability, but the first live causal run is staged.

### Gate A — implementation validation

No target-scored provider run. Deterministic fake-provider tests must prove:

- arm prompts are byte-identical except feedback numbers;
- hidden source text never enters proposer prompts or cache request IDs;
- true outcome scoring is always against the correct target, including decoy/null arms;
- decoy feedback uses only the preregistered paired target;
- checkpoint curves are truncations of one trajectory;
- arm order is counterbalanced and persisted;
- exactly one logical generation call occurs per step per arm;
- partial observations survive operational failure, while the failed cell remains invalid.

### Gate B — causal pilot

Only after a generation substrate is prospectively frozen by the target-free reliability program.

Pilot: all **24 targets**, **1 fresh trajectory per arm**, maximum **16 steps**, for 24 × 3 × 16 = 1152 logical generations. This gives 24 independent target-level paired effects without pseudoreplication and avoids paying for B=32 before the mechanism shows any sign.

Checkpoints: 2,4,8,16.

The pilot is not allowed to tune prompts or arm definitions after outcomes are seen.

### Gate C — confirmatory extension

Only if Gate B supports target-relevant feedback under the preregistered decision rule. Extend the same frozen trajectories prospectively to B=32 only if exact continuation is operationally possible; otherwise preregister a fresh confirmatory run before sampling.

A negative Gate B result is sufficient to reject or substantially weaken the scalar-feedback mechanism in the tested regime. It must not trigger rescue tuning inside v2.

## 10. Decision rule

The mechanism hypothesis is supported only if, across targets:

1. `true_feedback` shows a positive paired advantage over **both** `decoy_feedback` and `null_feedback` on the best-so-far trajectory; and
2. the sign is not explained solely by a larger candidate-score variance or an isolated lucky maximum; and
3. the advantage is visible in at least one trajectory-sensitive secondary metric (for example AUC or improvement frequency); and
4. operational validity meets the prospectively frozen reliability gate.

No p-value threshold is used as a sole success criterion. Report the full distribution of target-level paired effects and uncertainty.

### Kill criterion

Evidence weighs against the Perquire scalar-feedback mechanism if `true_feedback` is not meaningfully better than decoy/null feedback across targets, or if any apparent final-max advantage disappears in trajectory-sensitive measures.

In particular, if target-irrelevant decoy feedback performs comparably to true feedback, the claim that the target similarity numbers are supplying useful causal information is rejected for this regime.

## 11. Failure policy

- Provider failure does not disappear and does not trigger rerun-until-success.
- A failed trajectory is invalid for the primary endpoint.
- **All observations completed before failure must still be preserved**, together with the failure step and accounting.
- Operational retries remain transport accounting, not new logical samples.
- No silent model switching is allowed inside a frozen causal run.
- Replay reproduces historical observations and is never counted as a fresh replicate.

The exact minimum-validity threshold for Gate B must be frozen together with the selected generation substrate before target-scored execution.

## 12. Reliability substrate boundary

The current OpenRouter v2 observatory is a **selector/qualification program**, not the scientific experiment.

Before Gate B:

- a specific generation model/configuration must be frozen prospectively;
- the freeze must be based only on target-free capability/reliability evidence;
- observatory target scores/adaptive performance must not participate in substrate selection;
- route/account reliability must be observed longitudinally, not inferred from a single 10/10 or 20/20 window;
- once frozen, the causal experiment must not dynamically rediscover a different model per cell.

## 13. Construct-validity boundary

The optimized outcome remains model-specific cosine. Therefore a positive Gate B establishes only that target-relevant scalar feedback helps search **in that measured space**.

The stronger claim — useful semantic recovery — requires a separate held-out evaluator. The multi-space `SemanticStore` is infrastructure for that later test, not evidence by itself.

## 14. External validity

This v2 mechanism result generalizes, at most, to:

- the frozen generation model/provider configuration;
- the frozen optimization embedder;
- the 24 short English benchmark cases and represented domains;
- the tested 2–16 (and later 32, if confirmed) evaluation regime.

Generalization to other languages, document lengths, embedders, generators, or real corpora requires replication.

## 15. Prohibited post-outcome changes

After any Gate B target score is observed, the following define a new experiment version:

- changing arm semantics;
- changing prompt template;
- changing decoy pairing;
- changing parser selection rule;
- changing model/provider/routing policy;
- changing checkpoints or maximum budget;
- changing primary outcomes or target-level unit;
- dropping hard cases/domains;
- adding contrastive probes or other algorithmic mechanisms to rescue a negative result.

Negative evidence is an accepted terminal result for v2.
